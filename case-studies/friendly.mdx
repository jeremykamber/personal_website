## Context

I worked on Friend-ly as a mobile engineer. The idea was simple: university students are surrounded by thousands of people but still feel isolated. The app was a mobile-first social network designed for campus life — study groups, events, messaging, the kind of connections that happen when you're in the same place but need a way to find each other.

---

## Problem / Product Goal

Building a social network for students means solving a contradiction. You need a lively, energetic product that makes connection feel effortless, but the underlying infrastructure has to be rock-solid. Real-time messaging, media feeds, instant notifications — one state sync failure and trust is gone.

The product side was about reducing friction. How do you make forming a study group feel as natural as scrolling a feed? The engineering side was about one thing: keeping the app fast and consistent on any device, regardless of network conditions or content load.

---

## Thought Process

I chose React Native for the cross-platform reach. We needed both iOS and Android without maintaining two codebases, and React Native was mature enough by 2024 to deliver a native feel.

The architecture choice was MVVM — Model-View-ViewModel. The benefit is strict separation between business logic and UI. The ViewModels contain all the data-fetching and state logic; the Views are just components that render whatever the ViewModel tells them to. This matters for a few reasons.

First, testability. You can write tests against the ViewModel without spinning up a full UI environment. Logic tests run in milliseconds, and they catch the bugs that matter — wrong data flowing through the wrong path. Second, consistency. The same data-fetching pattern is used across the app, so you don't end up with three different ways to load a user feed. Third, separation of concerns. UI designers could work on View components without worrying about breaking API integration, and vice versa.

The design language was the fun part. We wanted energetic — bold colors, large readable typography, nothing shy about it. The vibe was meant to match campus life, not a corporate productivity tool. Making "find a study group for calc" feel engaging required some visual confidence.

---

## Solution

Cross-platform React Native app using MVVM architecture for state management and data flow.

The ViewModels handled all business logic — fetching feeds, managing chat state, syncing notifications. The Views were purely presentational, observing ViewModel state and rendering accordingly. This kept the codebase organized as features grew, and it made debugging much easier: when something broke, it was either a logic error in the ViewModel or a rendering error in the View, and you knew which category to look in.

The design system used bold accent colors, generous whitespace, and large typography. The goal was to make the app feel alive without being overwhelming.

---

## Takeaways

**Predictable state management is everything in a real-time app.** If your state is out of sync — a message shows delivered but wasn't, a feed shows stale content — the user notices immediately and trust drops. MVVM helped with this because state mutations followed a single, traceable path through the ViewModel. No random state updates scattered across components.

**Cross-platform still has sharp edges.** React Native handled 90% of what we needed, but the last 10% — performance on low-end Android devices, camera integration, push notification reliability — required native modules and platform-specific code. Plan for that margin.

**Social apps live and die on first impression.** We put serious effort into the onboarding flow and the first feed render. If the app felt slow or empty in the first 30 seconds, users rarely came back. Everything else was secondary.
