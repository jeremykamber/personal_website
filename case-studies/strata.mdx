Most memory systems treat all information the same way. A conversation from five minutes ago gets the same treatment as a decision from six months ago. Same storage cost. Same retrieval method. Same everything.

This is wasteful. Information decays over time, and your storage should reflect that.

**Strata separates the *decision* to move data from the *act* of compressing it.** Competing systems (mem0, OpenClaw, LangMem) use LLMs to constantly monitor and reorganize memory — every query triggers a check, every operation runs a janitor loop. Strata flips this: **algorithmic triggers** (file modification time, last access date, access count) decide *when* to move data. No AI needed. Only when a trigger fires is anything smarter invoked — and in the current architecture, even that step is just moving a file. No LLM, no compression, no token cost.

## The Architecture: Three Geological Strata

Memory lives in three filesystem directories, each with distinct latency and cost characteristics. Files move between them automatically based on age and access patterns.

### 1st Stratum — Active (`active/`)

Working memory. The agent reads and writes plain markdown files directly. No database, no vector index, no API calls.

- **Latency:** ~1ms. **Cost:** Zero.
- An auto-generated `index.md` lists every file with its first heading as a description — the agent reads this map to navigate, not a vector database.
- Access tracking via file modification time.

```python
# From strata/storage.py:Stratum1Storage
class Stratum1Storage:
    def write(self, path: str, content: str) -> Path:
        resolved = self._resolve(path)  # path traversal prevention
        resolved.parent.mkdir(parents=True, exist_ok=True)
        resolved.write_text(content, encoding="utf-8")
        return resolved
```

### 2nd Stratum — Cooled (`cooled/`)

When a file exceeds its decay threshold (default: 14 days for projects, 60 for entities, 7 for GTD tasks), the **Janitor** moves it to `cooled/`. Files stay as plain markdown — nothing is lost.

- **Read-only via search** — the agent can query cooled files but not write to them directly.
- **Bidirectional lifecycle:** If a cooled file is accessed ≥3 times (`promotion_threshold`), it gets automatically promoted back to active. Files cycle in both directions.
- Access is tracked via a lightweight JSON sidecar (`stratum_2_access.json`) — no database needed.

### 3rd Stratum — Archive (`archive/` + `shadow.db`)

When a cooled file hasn't been accessed for 90 days (`lru_days`) with ≤1 access, the Janitor **evicts** it to archive.

- Full content saved as JSON blob. A **Shadow Index** (SQLite with FTS5 full-text search) keeps it keyword-searchable — keywords + 200-character preview + file path. No vectors, no embeddings.
- **A million archived entries cost less than a megabyte.** You never truly lose anything — it just gets put away until you need it again.
- **Rehydration:** `strata rehydrate <shadow_id> --target=active|cooled` restores archived files. Auto-rehydration on read means searching for an archived file by path brings it back automatically.

## The Janitor: Algorithmic Lifecycle Management

The Janitor (`strata/janitor.py`) is the only process that moves data between strata. It uses deterministic rules — zero LLM calls.

| Operation | Direction | Trigger | Code |
|-----------|-----------|---------|------|
| **Migrate** | 1st → 2nd | File age ≥ decay threshold | `janitor.py:26-60` |
| **Evict** | 2nd → 3rd | Age ≥ `lru_days` AND access ≤ `lru_min_access_count` | `janitor.py:62-90` |
| **Promote** | 2nd → 1st | Access count ≥ `promotion_threshold` (default: 3) | `janitor.py:94-135` |
| **Rehydrate** | 3rd → 1st/2nd | Manual or auto on `strata read` | `janitor.py:137-175` |

**Full cycle order:** Distill → Promote → Migrate → Evict. Distill runs first so transcripts are processed before they could be migrated. Promote runs before Migrate so promoted files aren't immediately re-migrated. This ordering was a hard-won lesson from early testing — getting the cycle order wrong caused files to oscillate between strata.

Every operation supports `dry_run=True` for previews. The daemon's first cycle is always a dry run.

## The Shadow Index

When a file gets archived, the Janitor doesn't delete it. It stores a lightweight entry in SQLite FTS5:

```
shadow_index: id, original_path, keywords, archive_path, summary_preview, evicted_at
shadow_fts: FTS5 virtual table (auto-synced via triggers)
```

A keyword search against the Shadow Index is enough to decide whether a memory is worth rehydrating. No vector embeddings, no reranking. When a search finds something in the archive, the file gets automatically pulled back into active — the memory comes back because it proved useful again.

This is what separates Strata from systems like mem0 or QMD. Those either grow forever (infinite storage cost) or delete permanently (irrecoverable loss). The Shadow Index gives you an **infinite memory horizon at near-zero storage cost.**

## Design Decisions & Trade-offs

### Zero-Dependency Core

The package has **zero pip dependencies**. Not even `requests` — LLM API calls use stdlib `urllib.request`. Optional extras (`[openai]`, `[anthropic]`, `[all]`) add providers. QMD is an optional npm dependency for hybrid search.

**Trade-off:** More verbose HTTP code. **Benefit:** Zero supply chain risk, instant `pip install`, no version conflicts.

### Filesystem-First, Not Database-First

Every memory is a plain markdown file. `cat`, `echo`, `grep`, `git` all work. Files are the most agent-native format.

**Trade-off:** No native relational queries or vector search. **Benefit:** Any agent tool can read/write memories without an SDK.

### Algorithmic Janitor, No LLM for Lifecycle

This is Strata's core differentiator. Migration, eviction, and promotion use only file age + access count. Compare to mem0 (LLM per query), OpenClaw (LLM per operation), LangMem (LLM per embedding). The Janitor doesn't need to be smart — it needs to be *reliable*.

### LLM Compression Removed

The original blog post described compressing 3,000-word documents to 200-word summaries at migration. The implementation copies files as-is. **Rationale:** cost, latency, information loss, cheap storage. A 10KB markdown file costs nothing to keep at full fidelity.

### Multi-Component Path Matching

Different content types have different decay rates. The config system (`config.py:get_decay_days()`) checks progressively longer path prefixes — "pi/conversations" (7 days) takes priority over "pi" (30 days) takes priority over the default (60 days). This was surprisingly tricky to implement correctly with edge cases around path ordering.

## The Daemon

`strata serve` starts a background Janitor (`StrataDaemon`, `daemon.py:8-170`) that runs migration and eviction on a configurable interval (default: 900s / 15 minutes).

- First cycle is always a dry run (unless `--live` flag)
- Graceful shutdown on SIGINT/SIGTERM
- PID file at `strata.pid`
- Logs to `strata.log` with cost data tracking
- Optional systemd service via `strata install-service`

## Pi Integration: Strata in Practice

Strata is designed to be the memory layer for AI coding agents. The pi extension (`skills/pi/strata.ts`) hooks into the agent lifecycle:

1. **`before_agent_start`**: Injects Strata architecture into the agent's system prompt — the agent knows about three tiers, CLI commands, and `strata add`/`strata search` patterns at every session start.
2. **`agent_end`**: Saves the full conversation transcript to `pi/conversations/YYYY-MM-DD/YYYMMDDTHHmmss-{hash}.md`. No heuristic filtering — raw data is always preserved.

**Background distillation** (optional, daemon-driven): When `pi-config.json` has `llm.enabled: true` and a valid API key, the daemon scans for undistilled transcripts, sends them in one batch to a cheap LLM (default GPT-4o-mini), and writes extracted facts to `pi/facts/`. Cost: ~$0.01 per 15-min cycle. Disabled by default.

A **skill install** command (`strata skill install`) teaches agents about Strata via the Vercel Skills protocol, supporting 55+ agent formats (OpenCode, Claude Code, Cursor, Codex, Windsurf, etc.).

An **MCP server** (`strata mcp`) exposes six Strata tools over JSON-RPC 2.0 for Claude Code and Claude Desktop compatibility.

## What I Learned

The original design had LLM compression built into the migration step. You'd feed a raw file to GPT-4o and get back a 200-word summary with entity tags. It worked, but it was *overkill*. The Janitor doesn't need to be smart. It needs to be reliable.

Moving to a filesystem-only architecture eliminated the most expensive operation in the system. The Janitor went from "call an API and parse JSON" to "check a timestamp and maybe copy a file." The lifecycle logic got simpler, the tests got faster, and the system became truly zero-dependency. **This was the single most important decision in the project.**

The Shadow Index turned out to be the most important piece. I initially thought of it as a minor feature, but it's what separates Strata from systems like mem0 or QMD. Those either grow forever or delete permanently. The Shadow Index gives you an infinite memory horizon at near-zero storage cost. You never truly lose anything. It just gets put away until you need it again.

**Forgetting is the feature.** Information decays on purpose. That's what makes memory useful. The right question isn't "how do I store everything?" — it's "how do I store each piece at the fidelity it deserves?"
